# START HERE — пакет задач для Codex

**Снимок исследования:** 22 августа 2026 года  
**Цель:** улучшить `vadimohka.com`, начиная с бренда и доказательной архитектуры, а затем перейти к UX, accessibility, SEO и технической надёжности.

## Что находится в архиве

Архив рассчитан на распаковку **прямо в корень репозитория**. Он создаёт только:

- `qa/site-improvement-pack/` — исследования, evidence ledger, copy briefs, независимые задачи, тесты, промпты и безопасные шаблоны `AGENTS.md`/skill.

Пакет помещён в `qa/`, потому что проверенный deployment исключает этот dev-only каталог из публикации сайта. Перед merge Codex обязан подтвердить, что workflow по-прежнему исключает `qa/`.

Постоянные root-инструкции не устанавливаются автоматически: проверенный workflow не исключал `AGENTS.md` и `.agents`. Безопасный optional bootstrap описан в `install/BOOTSTRAP.md`.

## Как запустить

1. Сделайте резервную ветку.
2. Распакуйте архив в корень репозитория.
3. Откройте Codex из корня репозитория.
4. Передайте ему содержимое `qa/site-improvement-pack/MASTER_PROMPT.md`.
5. Codex прочитает вложенные instruction templates напрямую; root-установка необязательна.
6. Для последовательной работы начните с `B00`, затем идите по `manifest/task-order.md`.
7. Для одной задачи используйте `prompts/RUN_SINGLE_TASK.md`.

## Принцип работы

- Каждая задача самостоятельна, имеет собственные acceptance criteria и может быть отдельным commit/PR.
- Brand phase выполняется до Technical phase.
- Неизвестные факты не заменяются правдоподобным текстом.
- Публичные claims должны иметь evidence status.
- Codex не должен мигрировать сайт на framework и не должен добавлять production-зависимости.
- После каждого изменения запускается существующий `node qa/check.mjs`, затем проверки конкретной задачи.

## Что заполнить владельцу сайта

Файл `evidence/owner-input.example.yaml` содержит сведения, которые невозможно безопасно получить из публичных источников: точная роль в Century, direct email, разрешённые client references, deployment metrics, team scope, diligence mandates и точный MIPT credential.

Скопируйте его как `evidence/owner-input.local.yaml`, заполните известные поля и **не коммитьте конфиденциальные данные**. Codex обязан использовать консервативный fallback, если файл отсутствует.

## Главный риск, который устраняет пакет

Текущий сайт формирует сильное визуальное ощущение senior-level специалиста, но часть заявлений сильнее опубликованных доказательств. Поэтому первые задачи не «украшают» сайт, а выстраивают цепочку:

**Identity → Authority → Proof → Relevance → Depth → Trust → Action**
