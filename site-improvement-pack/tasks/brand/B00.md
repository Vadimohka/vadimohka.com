## Goal

Create a maintainable source of truth for claims before rewriting public copy.

## Why this task exists

- The current site repeats role, sector, metric and authority claims across visible HTML, metadata, JSON-LD and AI-readable files.
- The supplied CSV registers are a researched starting point, not a permanent unreviewed truth.

## Primary target files

- `qa/brand/claims.json`
- `qa/brand/sources.json`
- `qa/brand/README.md`
- `.gitignore`

The file list is a starting point. Inspect the current repository and include all claim or navigation mirrors affected by the change.

## Required inputs

- `qa/site-improvement-pack/evidence/claim-register.csv`
- `qa/site-improvement-pack/evidence/source-register.csv`
- `qa/site-improvement-pack/evidence/claim-policy.md`
- `qa/site-improvement-pack/context/content-model.md`

Also read:

- root `AGENTS.md` if installed, otherwise `qa/site-improvement-pack/install/AGENTS.md`;
- root skill if installed, otherwise `qa/site-improvement-pack/install/.agents/skills/vadimohka-site-upgrade/SKILL.md`;
- the current target files;
- relevant rows in `evidence/claim-register.csv` and `evidence/source-register.csv`.

## Implementation requirements

- Inspect all production HTML, `ai-profile.md`, `llms.txt`, `llms-full.txt`, `data/entity-graph.json`, and `sources.html` for substantive claims.
- Create `qa/brand/claims.json` and `qa/brand/sources.json` using stable IDs and the schema in `context/content-model.md`.
- Import the supplied evidence register, then add any current claims that appeared after the snapshot.
- Record exact text variants and all surfaces where each claim appears.
- Add a rule that a claim with `unverified`, `remove_or_clarify`, or `company_level_only` status cannot be used as personal hero proof.
- Ensure `owner-input.local.yaml`, screenshots containing private data, and any private evidence directory are ignored by Git.
- Document the update process and the distinction between owner-confirmed, independently verified and company-level evidence.
- Do not change public marketing copy in this task except to remove an accidental secret or a clearly dangerous placeholder.

## Non-goals

- No homepage rewrite.
- No visual redesign.
- No publication of private evidence.
- No assumption that the pack CSV is exhaustive.

## Acceptance criteria

- Every substantive public claim has a stable claim ID or is explicitly classified as non-claim copy.
- Every claim record has status, scope, surfaces, last-checked date and zero or more source IDs.
- Every source record states exactly what it supports and its caveat.
- Local owner-input files are excluded from Git.
- The ledger distinguishes personal, company-level and product-level facts.
- `node qa/check.mjs` still passes.

## Verification

- Parse both JSON files with Node.
- Search the repository for `owner-input.local`, private client names and common secret patterns.
- Compare the list of claim surfaces against every production page and machine-readable file.

Always run:

```bash
node qa/check.mjs
```

Run any additional task-specific test introduced by the implementation.

## Result record

Create or update:

`qa/site-improvement-pack/results/B00.md`

Use `qa/site-improvement-pack/templates/task-result.md`. Include all claim IDs changed, source IDs used, tests run, screenshots/manual checks, unresolved owner inputs, and rollback notes.

## Rollback boundary

This task must be revertible without reverting unrelated tasks. Do not mix opportunistic cleanup into the same change.
