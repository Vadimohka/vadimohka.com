## Goal

Present a rigorous assessment method without pretending to be an investor or established transaction adviser.

## Why this task exists

- The current page explains what would be examined but does not prove completed diligence engagements.
- The defensible value is an operator's technical assessment, not capital-allocation authority.

## Implementation requirements

- Change the title/H1 toward AI Technical Due Diligence.
- Define the decision: whether product, data, architecture, team and deployment claims survive operating scrutiny.
- Present assessment dimensions from the page brief.
- Describe inputs, process, deliverables and typical boundaries.
- Add a clear disclaimer that the work is technical assessment, not legal, financial, accounting or regulated investment advice.
- Use examples as assessment questions, not implied case results.
- Add a redacted sample-deliverable slot only if an actual safe file exists; otherwise explain the deliverable in text.
- Use CTA `Request AI technical diligence`.
- Avoid fund, transaction, deal, mandate or investment-outcome claims unless verified.

## Non-goals

- No investor persona.
- No implied completed mandate.
- No regulatory/legal advice.

## Acceptance criteria

- The page states scope, method, deliverable, limitations and CTA.
- No reader could reasonably infer that Vadim is presenting himself as a fund manager or investment adviser.
- No engagement count or transaction outcome appears without evidence.
- Metadata uses `AI Technical Due Diligence`.
- `node qa/check.mjs` passes.
