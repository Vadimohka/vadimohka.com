## Goal

Convert thin public-authority pages into a verifiable archive and an honest topical-authority foundation.

## Why this task exists

- A few valid 2026 public records now exist, but they should be organised rather than inflated.
- The Writing page is too thin to sustain an established thought-leader claim.

## Primary target files

- `expert.html`
- `writing.html`
- `origin.html`
- `sources.html`
- `assets/site.css`

The file list is a starting point. Inspect the current repository and include all claim or navigation mirrors affected by the change.

- `qa/site-improvement-pack/copy/page-briefs/about.md`

## Implementation requirements

- Rename/reframe Expert as Media & Speaking while keeping the existing file URL in stage one.
- Use structured records with format, title/topic, outlet/event, date, exact role and source link.
- Add 25/50/100-word bios from the copy pack, conditional on current role verification.
- Define a short list of speaking topics aligned with enterprise AI production, governance, diligence and product architecture.
- Reframe Writing as Insights and create topic pillars.
- Promote the verified 2026 Vaiti article and any verified existing article with correct dates.
- Add a content backlog link or internal editorial plan, not fake published articles.
- Add Article schema only to real article pages if/when created.
- Rebalance About/Origin so current operating work precedes the education narrative.
- Provide media/speaking CTA routes without inventing a direct email.

## Non-goals

- No fake article cards.
- No global speaker or thought-leader language.
- No publication dates inferred from file timestamps.

## Acceptance criteria

- Every displayed media/speaking item is linked and dated.
- Insights clearly distinguishes published work from planned topics.
- About uses exact roles/dates and contains no vague credential.
- Bio variants are internally consistent.
- `node qa/check.mjs` passes.

## Verification

- Validate each public record against source register.
- Search for unlinked cards and unsupported authority labels.
- Check heading hierarchy and responsive card layout.

Always run:

```bash
node qa/check.mjs
```

Run any additional task-specific test introduced by the implementation.
