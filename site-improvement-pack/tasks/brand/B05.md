## Goal

Turn the page from broad AI implementation language into a credible governed-deployment offer.

## Why this task exists

- Banks and regulated institutions need evidence of control, boundaries and operating ownership.
- The current language is conceptually strong but uses broad claims and does not clearly define engagement outputs.

## Primary target files

- `enterprise.html`
- `assets/site.css`
- `sources.html`

The file list is a starting point. Inspect the current repository and include all claim or navigation mirrors affected by the change.

## Implementation requirements

- Use H1 `Private AI systems for regulated organisations.` or an equally concrete verified version.
- Describe the decisions addressed: use-case selection, architecture, data access, governance, evaluation, ownership, integration and production readiness.
- Show a clear path from decision to controlled production without claiming guaranteed delivery.
- Add governance/security topics: access boundaries, source grounding, audit, observability, human review and deployment model, only where supported.
- Define engagement deliverables and boundaries.
- Use sector language as focus/design context unless a personal case is available.
- Add one verified product/case proof and one relevant public insight.
- Use CTA `Scope a governed AI deployment`.
- Keep copy readable for executives; avoid turning the page into a technical feature dump.

## Non-goals

- No security certification claim.
- No named bank logos without permission.
- No generic AI-transformation promise.

## Acceptance criteria

- A banker can identify the decision, controls, deliverables, evidence and next action.
- No wording implies a named banking deployment without proof.
- The page separates method from achieved outcomes.
- Relevant source links are present.
- `node qa/check.mjs` passes.

## Verification

- Search for broad sector claims and inspect their evidence.
- Test CTA and internal links.
