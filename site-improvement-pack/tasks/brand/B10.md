## Goal

Give every audience a clear, functional next action without rendering a fake form.

## Why this task exists

- The current contact flow sends users mainly to LinkedIn or another website.
- A static site cannot support a real form without an endpoint or architecture decision.

## Implementation requirements

- Use Contact H1 `Start with the decision that needs to be made.`
- Create routes for Enterprise deployment, AI diligence, CTO diagnostic, Executive briefing, Media comment and Speaking invitation.
- Use query parameters or fragments to preselect/highlight the relevant route from audience pages.
- Publish a direct professional email only when owner-approved.
- Keep LinkedIn as a functional fallback.
- Render a form only when a tested endpoint and privacy approach exist; otherwise use clear links/cards.
- Add `Do not include confidential data in the first message.`
- Do not invent response time or availability.
- Replace generic CTAs across the site with the map in `copy/navigation-and-cta.md`.
- Ensure every CTA has descriptive accessible text and a working destination.

## Non-goals

- No calendar integration without owner URL.
- No collection of personal data without privacy handling.
- No dead form control.

## Acceptance criteria

- Each primary audience has a distinct functional route.
- No CTA leads to an ambiguous or circular destination.
- No non-functional form appears.
- Keyboard and screen-reader users can identify every action.
- No private contact information is published without permission.
- `node qa/check.mjs` passes.

## Verification

- Click every CTA from every page.
- Test preselection/highlighting with query/fragment values.
- Check keyboard focus order and accessible names.
- Search for `href="#"`, empty href, fake submit and invented response-time copy.

Always run:

```bash
node qa/check.mjs
```

Run any additional task-specific test introduced by the implementation.
