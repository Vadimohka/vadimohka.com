## Goal

Remove canonical inconsistencies and document hosting limitations without pretending GitHub Pages supports arbitrary redirects.

## Why this task exists

- The root URL has had slash inconsistencies, and `/index.html` can remain reachable as a duplicate with canonical consolidation.
- A canonical tag is not an HTTP redirect.

## Primary target files

- `*.html`
- `sitemap.xml`
- `sitemap-images.xml`
- `sitemap-ai.xml`
- `robots.txt`
- `.github/workflows/*`
- `README.md`
- `qa/check.mjs`

The file list is a starting point. Inspect the current repository and include all claim or navigation mirrors affected by the change.

## Required inputs

- `qa/site-improvement-pack/research/repo-inventory.md`
- `qa/site-improvement-pack/context/information-architecture.md`

Also read:

- root `AGENTS.md` if installed, otherwise `qa/site-improvement-pack/install/AGENTS.md`;
- root skill if installed, otherwise `qa/site-improvement-pack/install/.agents/skills/vadimohka-site-upgrade/SKILL.md`;
- the current target files;
- relevant rows in `evidence/claim-register.csv` and `evidence/source-register.csv`.

## Implementation requirements

- Use `https://vadimohka.com/` consistently for the root canonical and sitemap entry.
- Ensure every sitemap URL is indexable and canonical.
- Use meaningful `lastmod` values only when content actually changed.
- Keep `sources.html` noindex only if it remains a raw evidence utility; reconsider if it becomes a polished evidence page.
- Confirm `robots.txt` references valid sitemaps.
- Document `/index.html` behavior and the options for a real edge/CDN 301.
- Do not add a JavaScript/meta refresh and call it a 301.
- Check www/non-www and HTTP/HTTPS behavior when network access exists.
- Ensure the dev pack, QA files and local inputs are not published or indexed.
- Add QA for canonical/sitemap exact-match rules.

## Non-goals

- No URL migration without redirects.
- No hreflang without complete alternates.
- No invented redirect verification.

## Acceptance criteria

- Root slash representation is consistent.
- Sitemaps contain no non-canonical or noindex page unless intentionally documented.
- Robots references resolve.
- The README accurately states redirect limitations.
- Deployment excludes QA/private files.
- `node qa/check.mjs` passes.

## Verification

- Parse all sitemap XML.
- Compare canonical URLs to sitemap URLs.
- Inspect deployment artefact or `_site` output.
- Use `curl -I` on host variants when network access exists and record actual status codes.

Always run:

```bash
node qa/check.mjs
```

Run any additional task-specific test introduced by the implementation.
