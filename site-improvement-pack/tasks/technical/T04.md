## Goal

Make search engines and AI systems receive the same conservative identity as human readers.

## Why this task exists

- Metadata exists, but several titles are generic and Person properties vary by page.
- Structured data must not contain broader claims than visible pages.

## Implementation requirements

- Apply the metadata map, adjusting only for verified owner inputs and current page architecture.
- Create one stable Person `@id`, such as `https://vadimohka.com/#person`.
- Create a connected WebSite node and page-level WebPage/ProfilePage nodes as appropriate.
- Model StackLevel as an Organisation with its official URL and the exact verified relationship.
- Model Century as Product/SoftwareApplication/Organisation only according to its real legal/product nature; do not guess.
- Use `sameAs` only for real profiles referring to the same person.
- Remove vague or unverified `alumniOf`, job titles, sectors and expertise properties.
- Add Article schema only to real articles.
- Set `inLanguage` and consistent canonical IDs.
- Validate every JSON-LD block and add QA for schema parsing and key consistency.

## Non-goals

- No fake review/rating schema.
- No Person award for the Century product placement.
- No Knowledge Panel promise.

## Acceptance criteria

- Every page's title, description, OG and X copy matches its visible purpose.
- All JSON-LD parses.
- One stable Person node is reused.
- No unverified role or education relation appears.
- Visible and AI-readable identities agree.
- `node qa/check.mjs` and structured-data tests pass.

## Verification

- Parse JSON-LD with Node.
- Compare all Person nodes/property values.
- Run a structured-data validator where network/tool access exists.
- Search machine-readable files for removed claims.
