| Field | Value |
|---|---|
| Phase | Technical |
| Priority | P1 |
| Impact | High |
| Effort | High |

## Goal

Ensure AI/search representations are conservative, current and fully aligned before release.

## Why this task exists

- Machine-readable files can silently preserve old claims after visible copy is corrected.
- The final release needs a single evidence and regression review.

## Primary target files

- `ai-profile.md`
- `llms.txt`
- `llms-full.txt`
- `data/entity-graph.json`
- `sitemap-ai.xml`
- `qa/*`
- `reports/release-report.md`

The file list is a starting point. Inspect the current repository and include all claim or navigation mirrors affected by the change.

## Required inputs

- `qa/site-improvement-pack/manifest/release-gates.md`
- `qa/site-improvement-pack/templates/release-report.md`
- `qa/site-improvement-pack/evidence/claim-policy.md`
- `qa/site-improvement-pack/research/suggested-test-matrix.md`

Also read:

- root `AGENTS.md` if installed, otherwise `qa/site-improvement-pack/install/AGENTS.md`;
- root skill if installed, otherwise `qa/site-improvement-pack/install/.agents/skills/vadimohka-site-upgrade/SKILL.md`;
- the current target files;
- relevant rows in `evidence/claim-register.csv` and `evidence/source-register.csv`.

## Implementation requirements

- Regenerate or manually synchronise all machine-readable profile files from the approved claim ledger.
- Remove any broader bank, investor, role, metric, education or authority claim than appears visibly.
- Ensure stable URLs, Person IDs, role dates and sameAs links.
- Update AI sitemap only with real public resources.
- Run static QA, browser tests, accessibility scans and performance baseline.
- Run an external-link check and record failures without silently deleting important evidence.
- Review deployment output to ensure QA pack, owner inputs and private evidence are excluded.
- Produce `reports/release-report.md` using the supplied template.
- List all unresolved owner inputs and deliberately omitted claims.
- Perform a final diff review for unrelated changes.

## Non-goals

- No new brand claim during final QA.
- No hidden machine-readable promotion.
- No release if P0 evidence risk remains.

## Acceptance criteria

- Visible and machine-readable identities match.
- All Brand and Final Release Gates pass.
- All required tests pass or an explicit blocker is recorded.
- No private/dev pack file is published.
- No public TODO, placeholder, dead source or unsupported claim remains.
- A complete release report exists.

## Verification

- Search all files for each removed/high-risk claim.
- Compare generated deployment tree to allowlist/exclusions.
- Run every command documented in the release report.
- Review live site after deployment if access is available.

Always run:

```bash
node qa/check.mjs
```

Run any additional task-specific test introduced by the implementation.

## Result record

Create or update:

`qa/site-improvement-pack/results/T10.md`

Use `qa/site-improvement-pack/templates/task-result.md`. Include all claim IDs changed, source IDs used, tests run, screenshots/manual checks, unresolved owner inputs, and rollback notes.

## Rollback boundary

This task must be revertible without reverting unrelated tasks. Do not mix opportunistic cleanup into the same change.
