## Goal

Make all primary destinations discoverable and operable on mobile and keyboard.

## Why this task exists

- At narrow widths the current navigation becomes a horizontally scrollable row, hiding later destinations.
- A menu must work without pointer-only assumptions.

## Implementation requirements

- Add a semantic menu button with an accessible name, `aria-expanded` and `aria-controls`.
- Use progressive enhancement: core links remain in the document and usable if JavaScript fails.
- Open/close with click, Enter and Space.
- Close with Escape and return focus to the trigger.
- Define predictable focus behavior; avoid a broken focus trap.
- Close on navigation and, if implemented, outside interaction without harming keyboard use.
- Prevent hidden menu links from receiving focus when closed.
- Remove dependency on horizontal-scroll discovery.
- Add a visible skip-to-main-content link as part of the same header accessibility work.
- Respect reduced-motion preferences.
- Keep desktop navigation behavior unchanged.

## Non-goals

- No third-party menu library.
- No complete header redesign.
- No full-screen animation.

## Acceptance criteria

- Every nav item is visible after one explicit menu action at 320 and 390 px.
- The menu is fully keyboard operable.
- Escape closes and restores focus.
- No hidden links are tabbable.
- The skip link is first or near-first in keyboard order and moves focus to main content.
- No general horizontal overflow at test widths.
- `node qa/check.mjs` passes.

## Verification

- Manual keyboard test using `research/suggested-test-matrix.md`.
- Automated browser test for expanded state, Escape and focus return.
- Test with JavaScript disabled.
- Capture 320, 390, 768 and 1440 screenshots.
