## Goal

Add development-only browser coverage for layout, menu, keyboard behavior and serious accessibility issues.

## Why this task exists

- Static parsing cannot prove rendering, focus management, horizontal overflow or accessibility behavior.
- Development-only dependencies are acceptable when they do not enter production output.

## Implementation requirements

- Prefer Playwright with axe-core as development-only tooling; document any alternative.
- Serve the site locally during tests.
- Test 1440×1000, 1024×768, 768×1024, 390×844 and 320×568.
- Check no document-level horizontal overflow.
- Test mobile menu open/close, Escape, focus return and JavaScript-disabled navigation.
- Test skip link and key CTA destinations.
- Run automated accessibility scans and fail on serious/critical violations.
- Capture deterministic screenshots or a lightweight visual baseline.
- Keep browser tooling out of the deployed site.
- Add a separate CI job or documented optional job if browser install time is material.

## Non-goals

- No claim of full WCAG conformance.
- No fragile pixel-perfect test for every decorative detail.
- No production JavaScript dependency.

## Acceptance criteria

- Browser tests cover all listed viewports.
- Mobile navigation and skip link have automated behavior tests.
- Serious/critical axe findings fail CI.
- Screenshots are reviewable and stable enough to detect major regressions.
- Production output contains no browser-test package.
- Baseline static QA still passes.

## Verification

- Run the full browser suite locally.
- Intentionally break menu focus and confirm a test fails.
- Inspect CI artefacts/screenshots.

Always run:

```bash
node qa/check.mjs
```

Run any additional task-specific test introduced by the implementation.
