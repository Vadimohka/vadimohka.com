## Goal

Turn recurring audit risks into automated failures without bloating the production site.

## Why this task exists

- The existing Node QA already checks HTML fundamentals, links/assets, IDs, sitemap and robots.
- It does not yet enforce claim/source, navigation, schema or production-TODO rules.

## Implementation requirements

- Preserve the pure-Node baseline and existing checks.
- Fail on production `TODO`, `[OWNER_INPUT_REQUIRED]`, empty/placeholder source links and fake form actions.
- Parse every JSON-LD block.
- Check that required metadata values are present and titles/descriptions are unique where expected.
- Check stable Person `@id` and exact current-role consistency.
- Check navigation destinations/order across pages.
- Check that every public-signal record has date, role/title and external URL.
- Check canonical URL and sitemap exact matches.
- Check that no QA/dev/private path is included in sitemap or deployment output.
- Add fixture or unit-style coverage for new failure modes without production dependencies.
- Document how to add a new approved claim/source.

## Non-goals

- No brittle natural-language assertion that blocks every copy edit.
- No network-dependent check in the required offline baseline.
- No replacement of browser testing.

## Acceptance criteria

- Each listed regression produces a clear actionable error.
- The checker remains deterministic offline.
- A clean site passes in CI.
- Known bad fixtures fail.
- Runtime remains reasonable for a small static site.
- README documents the checks.

## Verification

- Run `node qa/check.mjs`.
- Run each bad fixture or temporary mutation and confirm failure.
- Review CI output readability.

Always run:

```bash
node qa/check.mjs
```

Run any additional task-specific test introduced by the implementation.
