| Field | Value |
|---|---|

## Goal

Make the conversion UI functional and privacy-aware without adding a dead form.

## Why this task exists

- Brand task B10 defines the routes; this task implements robust behavior and optional form integration.
- Static GitHub Pages has no form backend.

## Primary target files

- `contact.html`
- `assets/site.css`
- `assets/site.js`
- `README.md`
- `qa/check.mjs`

## Implementation requirements

- Implement intent preselection through documented query parameters or fragments.
- Ensure the page remains useful without JavaScript.
- If no endpoint exists, render only functional email/LinkedIn/company links and inquiry guidance.
- If an endpoint exists, validate it in a non-production test, use explicit labels, autocomplete, error summary, inline errors and accessible success state.
- Add a privacy/data-handling note appropriate to the actual receiving entity.
- Do not request confidential data in the first message.
- Prevent spam-sensitive personal details from being committed when not approved.
- Add QA that rejects a form with missing/placeholder action.
- Document configuration without committing secrets.

## Non-goals

- No invented backend.
- No analytics event claiming conversion success.
- No calendar integration without URL.

## Acceptance criteria

- Every contact action works with JavaScript enabled and disabled.
- Any form has a real tested endpoint and accessible labels/errors.
- No placeholder endpoint or private secret exists.
- Intent preselection is stable and documented.
- `node qa/check.mjs` passes.

## Verification

- Submit a test inquiry only to an approved test endpoint.
- Keyboard and screen-reader-style form review.
- Search for placeholder domains, tokens and secrets.
- Test all query/fragment routes.

Always run:

```bash
node qa/check.mjs
```

Run any additional task-specific test introduced by the implementation.
